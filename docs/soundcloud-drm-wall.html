The SoundCloud DRM Wall

Around 200 tracks stopped downloading. It looked like a regional block for a week of debugging, and a proxy would have fixed that. It is not a regional block — SoundCloud retired the unencrypted renditions for this content, and no exit country brings them back.

Where it actually breaks

Downloading a track is four hops. The first two always succeed, which is why the failure was hard to place — the metadata keeps advertising a plain audio file long after that file stops existing.

01

Fetch track metadata

GET /tracks/{id} returns the policy, the real duration, and the list of transcodings. This always works, from every region tested.

02

Pick a transcoding

Our loader takes the first non-snipped progressive entry. It is listed, it is marked snipped: false, and its duration matches the full track — so selection succeeds and looks entirely healthy.

passes
03

Resolve the media URL — this is the break

Asking that transcoding for its CDN link returns 404 {}. The entry in the metadata is a leftover: SoundCloud kept advertising it after removing the file behind it. Only the cbcs / cenc entries resolve.

404 · plain renditions gone
04

Download the bytes

Reachable only via the encrypted lane. The segments download fine, but they are ciphertext. The key sits behind a license server that hands it to a certified decryption module inside the browser — never to an HTTP client.

Two different failures wearing one mask

The confusing part was that the same tracks reported two different things depending on where the request came from. They are two faces of one migration.

In an unlicensed region the API hides the track behind policy: SNIP and serves a 30-second preview. SoundCloud's own player says it plainly: Not available in Poland. This part really is regional, and a proxy really would lift it.

In a licensed region the block lifts and the full track appears — as four encrypted renditions. The unencrypted ones are listed but return 404. So changing region moves a track from one dead end to another.

Why no proxy, VPN or local client fixes it

The two failures need very different things, and only one of them is solvable by moving the request.

SNIP is a policy flag

A field in a JSON response. The server decides by IP what to show you. Nothing is encrypted — change the exit country and the field changes with it.

DRM is cryptography

The audio is AES-encrypted at rest on the CDN. The manifest carries an #EXT-X-KEY pointer to a license server, which releases the key only to Widevine, FairPlay or PlayReady after verifying the module's signature. Decryption happens inside that closed module and the decoded audio is never exposed to the page.

A proxy, a VPN, an OAuth token, or a downloader running on your own machine all issue ordinary HTTP requests. Every one of them receives the same ciphertext and none can obtain the key.

This is also why the plan to route downloads through a home machine would not have helped: it changes the exit IP, which was never the binding constraint for these tracks.

In production the same pattern covers 204 of 1002 stored songs, most of them holding a saved 30-second preview from before the check existed. The trend runs one way: SoundCloud is moving monetized catalogue onto encrypted HLS, so the 172 is a number that shrinks over time. That is not something the code can defend against.

What the investigation changed in the code

  • Snipped is now its own outcome. SoundCloudSnippedTrackException separates "restricted for this session" from "track is broken", so a regional block no longer looks like corruption.
  • Songs carry IsSnipped. A restricted track stays a retry candidate and clears itself on the first successful download, instead of being written off permanently.
  • Every run prints its session. SoundCloudSessionProbe reports the resolved region, whether authorization reached the runtime, and the policy for a probe track — this is what finally showed production egressing from KZ.
  • Load retries everything unplayable. IsLoadCandidate now includes stored files under 31 seconds, which had been silently skipped — 204 tracks in production had never been reconsidered.
  • Proxy and authorization are wired end to end, dev and prod, through Audio__Socks5Proxy and Audio__SoundCloudAuthorization. Useful for genuinely regional tracks, useless against DRM.

Worth doing next

Split a DrmOnly outcome away from Snipped. Right now the DRM-migrated tracks are retried on every load and fail every time. A track whose only resolvable renditions are *-encrypted-hls is permanently out of reach and should be recorded as such, not retried forever.

Findings verified by resolving individual transcodings against api-v2 from five exits (PL, KZ, DE, CH, US) and confirmed against SoundCloud's own web player. Track sample: 1820897418 and seven others from the same playlist.
